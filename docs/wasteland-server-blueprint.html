Wasteland Server Blueprint

A version lock, a mod stack tied to design pillars, a real endgame loop, and a phased rebuild sequence with a pass/fail gate at every stage.

Target 1.20.1 Forge World Full reset RAM 10–12 GB Pillars 6

The decision that governs everything

Version lock

Minecraft 1.20.1 on Forge

Not NeoForge, not 1.21.1. The binding constraint is TaCZ — the modern firearms mod that carries the whole weapons pillar. It has only ever shipped official Forge builds, and the newest is 1.20.1 (1.1.8-hotfix, May 2026). The 1.21.1 NeoForge build is an unofficial community port whose own notes warn that 1.20.1 world data is incompatible and that gun packs need a separate upgrader mod.

Every other load-bearing mod — Lost Cities, Superb Warfare, Enhanced Celestials, Improved Mobs, Lootr, Immersive Vehicles — has a maintained official 1.20.1 Forge build. 1.20.1 is the only version where the entire stack is first-party. Building on 1.21.1 buys newer worldgen and costs you the one mod you cannot replace.

World

The map resets. There is no migration path.

Lost Cities is the cornerstone of the setting — it replaces the overworld with a ruined cityscape rather than adding structures to one. It is a world generator, so it cannot be applied to existing terrain. If the current world is kept, the post-apocalyptic setting is off the table and the whole design collapses back into "vanilla with guns."

Announce the reset early and make it the season boundary. If anything on the current world matters, export it as a schematic before shutdown, not after.

Constraint worth knowing now

Mixing loaders is what produced the current mess. A 1.20.1 Forge server cannot run Fabric jars, and bridge layers that claim otherwise are the single most common source of the "works alone, crashes together" failures you're describing. One loader, one version, no exceptions — including for a mod someone really wants.

What I need to audit what's there

The review half of this can't start without the server's own files. Pull these from the Bisect panel — file manager, or SFTP into a zip — and the audit runs off them directly.

Server identity

Panel screenshot showing server type, MC version, loader build, allocated RAM, and the full startup command including JVM flags and Java version.

Mod inventory

Full filename listing of mods/. Filenames carry the version strings — that listing alone identifies most conflicts.

Configuration

config/, defaultconfigs/, kubejs/, scripts/, datapacks/ — zipped whole, not sampled.

Failure record

All of crash-reports/, plus the last three logs/ files. Crashes name the incompatible pair outright.

Runtime state

server.properties, ops.json, whitelist.json, world folder size, and the dimension folder listing.

Provenance

Whether this was installed from a Bisect one-click modpack and which one — and its version. That tells us what's pack baggage versus deliberate.

Population

Typical and peak concurrent players, and whether anyone expects their builds to survive. This sizes the hardware and settles the reset conversation.

What the audit reports back

  • Loader/version conflicts — jars built for a different MC version or loader than the server runs.
  • Duplicate function — two mods doing the same job, the usual cause of registry collisions and doubled worldgen. Modpack merges produce these by the dozen.
  • Dead weight — mods with no dependent and no gameplay role, each one still costing boot time and memory.
  • Abandoned dependencies — mods whose last release predates the server's MC version, which are the ones that break on every future update.
  • Config drift — settings that contradict each other across mods, e.g. two mods both claiming spawn control.
  • Client/server split errors — client-only jars on the server and vice versa.
  • Crash attribution — every crash report resolved to a named mod pair.

The output is a per-mod disposition: keep, replace, or cut, each with a reason. Nothing carries forward into the new build without one.

Pillars and the stack that serves them

Every mod in the build answers to a pillar. A mod that serves no pillar does not ship — that rule, applied without exception, is what stops the rebuild becoming the thing you're replacing. Roles: Load-bearing the pillar fails without it · Supporting makes it work properly · Optional flavour, cut first under load.

Overlap to resolve at build time

TaCZ and Superb Warfare both add small arms. Running both unmanaged gives players two parallel, non-interoperable ammo economies. Decide the split early: TaCZ owns personal weapons, Superb Warfare owns vehicles and crew-served weapons, and disable SBW's small arms in its config. This is the kind of duplication that makes a server feel incoherent even when nothing crashes.

III · Vehicles — mobility as progression

ModRoleBuildWhat it does here
Immersive Vehicles (MTS)Load-bearing1.20.1-22.18.0Content-pack driven cars, trucks and aircraft with fuel systems. The pack model means you choose the vehicle roster rather than accepting one.
Ultimate Car ModOptional1.20.1Alternative if MTS pack management proves fiddly. Adds road-building blocks and a biodiesel chain — good fit for reclaiming highways, but do not run both.

Immersive Engineering is the one tech mod the cut list makes an exception for: its concrete, scaffolding, wiring and diesel generators are the setting's own materials, and its biodiesel chain supplies the fuel economy below. It stays trimmed in config; Create and every other tech tree go.

Fuel is the design lever here. Make it a refined resource with a real production chain and vehicles become a progression tier rather than a spawn-in toy — you earn the truck, then you earn the fuel to use it, then the highway network becomes yours. Set fuel consumption before players get vehicles; raising it later reads as a nerf.

The negative finding worth planning around

FactionCraft does not exist on 1.20.1. The obvious answer to "hostile NPC factions that patrol, raid, and fight each other" was last released for 1.19.2 and is unmaintained. There is no drop-in replacement.

So factions are authored, not installed: In Control! rules define which mobs spawn in which districts and under which conditions, human-hostile mobs supply the bodies, and loot tables and gear give each faction a signature. This is more configuration work than any other part of the build — budget for it explicitly rather than discovering it in week three.

The hardest tuning problem on the server

Improved Mobs' block-breaking is what makes horde night matter and what will destroy every base you have if left open. Constrain it on three axes: restrict breakable blocks to a whitelist of soft materials, enable the aggressive tier only during a blood moon, and lean on FTB Chunks claims for permanent bases. Test this against a purpose-built base on the staging server before it ever touches live.

VI · Horror — the thing in the fog

ModRoleBuildWhat it does here
The Man From The FogSupporting1.20.1A stalker that watches from distance, closes when ignored, and vanishes or turns aggressive when looked at. Forge 1.20.1 — this is why the version lock also serves the horror pillar.
The One Who WatchesSupporting1.20.1Ambient dread rather than combat — surveillance, disorientation, escalating pressure. Pairs well with Man From The Fog if the rates on both are turned down.
Sound Physics RemasteredOptional1.20.1Occlusion and reverb. In an empty concrete city this does more for atmosphere than any entity does.

Both horror mods default to rates tuned for solo play. On a populated server, the same rate means the entity is on screen constantly and stops being frightening within a week. Cut spawn frequency hard — aim for a player encountering something roughly once every few sessions, not every night. Rarity is the mechanic.

The endgame problem, and a structure that answers it

You named the real difficulty: "amass weapons and tech to explore more locations" is a treadmill with no terminus. It fails on this engine for a specific reason — Minecraft has infinite space and no attrition, so reaching a place can never stay expensive. Once you have the gear, every remaining location is the same location.

The old premise had the Tarkov problem: once the players have max gear, every location is the same loop. So the cost moves from gear to time. Territory you can lose is the only scarcity the engine reliably provides, and with five players the loss has to be threatened one place at a time.

Strongpoints

Place five fixed, rare, faction-garrisoned compounds in the wasteland ring around the player district (their footprints are drawn in the world and on the district map) — a power substation, a water treatment plant, a hospital, an airfield, and a radio tower. Each can be cleared, and once cleared, held. Holding one grants a persistent server-wide unlock:

  • Substation — powers electric infrastructure and charging.
  • Water treatment — clean water, and the biodiesel chain that fuels vehicles.
  • Hospital — medical crafting and reduced death penalty.
  • Airfield — unlocks aircraft and heavy vehicle recipes.
  • Radio tower — the endgame objective, see below.

Taking a location starts a clock. The players get a set amount of time to build defences, structures and gear at that location before it is attacked on a set cycle. If they are defeated, or die, the position is lost and must be retaken from the garrison. If they win, the position is held, and holding it buys more time to explore and clear the next points of interest. Every cleared POI joins the pool from which the game draws, at random, the one that will be attacked next, with a warning ahead of time like a 7 Days to Die blood moon: the radio tower broadcast and the quest book name the site and the night. One site per attack; five players cannot hold five compounds and are never asked to. Every location also yields the loot that repairs the radio tower.

The Signal: a finale that comes to you

Repairing the radio tower needs the loot every held location drops. Completing it starts a countdown to the big one. When the timer runs out the finale is a wave defence at the players' main base, the hideout they have been living in, never at a strongpoint: escalating waves against the base, and the final wave carries the boss. The base is whichever claim the group marks as home in the quest book. The fight happens on ground the players built, with everything they own on the table.

Loop · 01

Scavenge

Instanced city loot funds the first assault. Gear is the entry fee, not the goal.

Loop · 02

Take

Clear a garrisoned location. The clock starts: a set time to fortify it before the first attack. Each held location unlocks a tech tier and adds itself to the target pool.

Loop · 03

Defend

On the cycle the game draws one held location and warns the players. Win and it stays held, with more time to explore; lose or die and it must be retaken.

Loop · 04

Signal

Tower repaired from the loot the locations drop, the countdown runs, and the waves come to the main base. The last wave brings the boss. Then the season increments and it starts harder.

The seasonal reset at the end is what keeps the server alive past completion. Bump the difficulty tier, reset the garrisons, open a new loot tier, keep the map. A server that can be finished and then has nothing is a server that empties the week after someone finishes it.

Implementation is FTB Quests for the visible progression and the home-claim marker, In Control! for garrison composition, KubeJS for the location state machine, the clock, the target draw, the countdown and the wave director, and The Hordes for the attack nights. All four are already in the stack for other reasons.

Operating rules that stop the mess coming back

  • A staging server exists. The cheapest Bisect tier running the same pack. Nothing reaches live that hasn't booted and been played on staging.
  • The district map lives at Wasteland District Map: every player build, the five strongpoint pads with sizes and coordinates, and the starting area.
  • Every mod is version-pinned. build/manifest.json and build/additions.json hold exact filenames, hashes and declared dependencies for the whole set. "Latest" is how a working server breaks overnight.
  • One change at a time after launch. Add a mod, run it for a few days, check Spark. Batched changes make attribution impossible — which is how the current server got where it is.
  • Configs are versioned. Keep config/, kubejs/ and the quest book in a git repo. Rolling back a bad tuning pass should take a minute.
  • Backups are tested. An untested backup is not a backup. Restore one to staging before you need it for real.
  • Every mod answers to a pillar. The single rule that matters most. A mod that is merely interesting is what turns a designed server back into a pile.

Rebuild sequence

Bottom-up, on the existing Bisect instance. Nobody has played since January 2026, so the live server is the staging server until launch. Each phase has a gate; a phase that fails its gate is re-run, not carried forward.

What carries over, and how

  • Jars marked Keep in the audit are copied off the current server, not re-downloaded — the running builds are the known-good ones. Two exceptions: TaCZ moves to 1.1.8-hotfix, and LC²H is re-pinned against Lost Cities 7.4.x.
  • Configs that carry: incontrol/spawn.json and spawner.json with the mech entries removed; MobFactions.toml likewise; dynamicview.json; tacz-common.toml; superbwarfare-*.toml; bandits.json; hostilevillages.json; guardvillagers-common.toml; zombieawareness/; lostcities/ with the chosen profile. Everything else regenerates.
  • The player builds move by transplant, not by keeping the world. The live player district (chunks x 56…193, z 24…129), the spawn structure, and eleven never-transplanted old-world sites are copied chunk-by-chunk into the new world after it generates, with cut-mod blocks remapped. Details in the audit's Player builds section.
  • Nothing else moves. Not the world wholesale, not config/, not defaultconfigs/, logs/ or crash-reports/. The orphan configs end here.
  • Additions, resolved on Modrinth to exact 1.20.1 Forge builds and hash-verified into build/mods: Lootr 0.7.35.94, Improved Mobs 1.13.7 (+ TenshiLib), FTB Chunks, Quests 2001.4.22, Library 2001.2.13, Teams 2001.3.2 and Item Filters (CurseForge CDN by file id — FTB does not publish on Modrinth), Canary 0.3.3, Xaero's Minimap 26.4.2 + World Map 1.45.0, The Man From The Fog 1.4, Immersive Vehicles 24.0.0, KubeJS 2001.6.5 (+ Rhino, Architectury), Simple Voice Chat 2.6.22, Apotheosis 7.4.8 (+ Apothic Attributes), Chipped 3.0.7 (+ Resourceful Lib), TaCZ 1.1.8-hotfix, Lost Cities 7.5.3. LC²H was tried and cut: its 3.5.0 build pins Lost Cities to a window narrower than one minor version.
  • The client pack is a by-product of the manifest. A Modrinth-format .mrpack built from the same pinned list, with CurseForge-only jars carried as overrides, so every player runs exactly the server's set.

Nothing is deleted — old content is renamed aside

  • /mods, /config and /defaultconfigs were renamed to …_old_20260902 through the panel API, and the new world uses a new level name, so the old worlds are never touched and every step reverses with a rename. This replaces the panel-side wipe that an earlier version of this plan called for.
  • No panel backup exists or can: this plan allows zero backup slots. The rollback is the complete local snapshot already taken — every world, mods, libraries, tacz, configs, logs — under Minecraft Server Tools\pull\. Nothing on the server is wiped until that folder is confirmed intact.
  • Startup → AIKARS_ENABLED = 1. The panel derives Xms from allocated memory; confirm it equals Xmx afterwards.
  • Housekeeping deferred to launch: the remnant worlds, the stray root region/, world/, serverconfig/, mods alternate/, tacz_backup/, the 531 MB zip and hs_err_pid123.log are deleted only after the new world is proven and the transplant verified — they are all in the local snapshot regardless.

The cut list

Categories to keep out of this build regardless of how good the individual mod is. Each one is a specific way a themed server loses its theme.

  • Magic and fantasy content packsDirectly contradicts the setting. The most common single cause of a themed server drifting into generic kitchen-sink.
  • Large tech mods (AE2, Mekanism, Create at scale)Each brings a full parallel progression that competes with the strongpoint loop and pulls players into base automation instead of the city. Immersive Engineering is the single exception, kept for its fuel chain and industrial look.
  • Additional dimensionsSplits an already thin player population across maps and drains the city of the people who make it feel dangerous.
  • A second gun modTwo ammo economies, two attachment systems, two balance curves. Pick one lane per weapon class and hold it.
  • Anything Fabric-onlyNot installable on this stack. Bridge layers that claim otherwise are a leading source of the failure mode being replaced.
  • Convenience mods that shortcut travelWaystones, teleport commands, and flight undercut exploration and vehicles at once — the two pillars the server is built on.
  • Unmaintained modsAnything whose last release predates 1.20.1 is a permanent block on ever updating the server.

Load-bearing mods were checked against their listings for 1.20.1 Forge availability and current build numbers as of September 2026: Lost Cities, TaCZ, Superb Warfare, Enhanced Celestials, Improved Mobs, Lootr, Immersive Vehicles, Ultimate Car Mod, The Man From The Fog, The One Who Watches, and the performance stack.
