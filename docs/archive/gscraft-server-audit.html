GSCraft Server Audit

What the server actually runs, how it broke, what is salvageable, and a keep / replace / cut verdict on all 138 jars.

Loader Forge 47.4.10 · MC 1.20.1 Java 17.0.20.1 Jars 138 · mod IDs 189 RAM 8 GB Last player 2026-01-16

Verdict

Rebuild

Rebuild from a clean install. Nothing here argues for repair.

The server boots and stays up, so the damage is not the crashing kind — it is content-level. Loot chests that generate empty, a gun mod whose entire crafting chain fails, a Fabric API bundle running inside Forge, five separate weapon systems, a 1.21 jar that Forge silently ignores, and config folders from at least two other modpacks on other loaders. Every one of those is invisible in the panel and present in the logs.

The good news is real: the loader and version already match the target (Forge 1.20.1), roughly a third of the jars carry straight into the rebuild, and the zombie-apocalypse spawn design in In Control! and Mob Factions is genuinely good work worth keeping.

World

The server has been empty since 16 January 2026.

Five players have ever joined; three were regulars. Activity peaked in July 2025 (57 join-days that month), fell to 9 in January 2026, and stopped. The only traffic since is a vanilla client at 213.152.161.54 probing the port every 42 minutes — a server-list scanner, not a person. Whitelist is off and the server is open to the internet.

Nobody to displace — but the world holds player-made sceneries that survive the reset by transplant, not by keeping the map. See Player builds below.

Three independent records tell the same story.

Every non-memory crash is the same event: a jar dropped in, restart, crash, another jar dropped in. That is the process the rebuild replaces with a pinned manifest and a staging server.

The mod count only ever went up

152 mod IDs in July 2025 → 157 in August → 164 in September → 184 on 30 October (one session added twenty) → 189 by January 2026. Nothing was ever removed except KubeJS. The out-of-memory crash happened at the low end of that curve.

The config folder holds three modpacks' worth of leftovers

  • Nine YUNG's "Better…" config files named -neoforge-1_21, plus three matching folders — from a NeoForge 1.21 pack. None of these mods are installed.
  • c2me.toml and lithium.properties — Fabric-only performance mods. They cannot run on this server and never have.
  • neoforge-common.toml, neoforge-server.toml — NeoForge's own config, on a Forge server.
  • Gravestone, Spore, Tree Harvester, Library Ferret, Better Village, Immersive Optimization — configs for mods no longer present. Two .bak files of Iron's Spellbooks server config alongside the live one.
  • The Hordes config folder is from Hordes 1.6.0 for Minecraft 1.21 (hordes-info.json says so) while the installed jar is 1.5.4c for 1.20.1. Its horde table references minecraft:bogged, a 1.21 mob, and errors at load. The mod falls back to its default table.

The server root is littered the same way

  • Two world folders. Escape From Minenkrafte is the live world; Escape From Minecraft (December 2025) is a remnant of an earlier one — 21 entries, mostly stats and server config.
  • A stray region/ at the root holding sixteen .mca files from October 2025, plus a stray world/ and a stray serverconfig/create-server.toml. Someone unpacked a world in the wrong place.
  • A 531 MB zip (73160fed-…, September 2025) sitting in the root — an old upload or backup that was never removed. It is the single largest object on the server.
  • mods alternate/ (empty) and tacz_backup/ (empty) — abandoned stashes.
  • Four of the live world's six datapacks are 1.21 builds — AFK Announcer, Show Dimension In Name, Sleep, and Farmer's Delight cutting recipes for Twilight Forest, all tagged [1.21] on a 1.20.1 server. The other two are No More Phantoms and a Superb Warfare uniform pack.
  • hs_err_pid123.log from 10 June 2026: a hard JVM crash (SIGSEGV) twenty seconds into boot. The stack is Spark's async profiler sampling the server thread during class loading — a profiler session had been left running across a restart, and the JVM race that triggers is a known one on that Java build. Not a mod fault; a reason never to leave /spark profiler running unattended.

What is broken right now

From the current boot log: 73 error lines, 80 warnings, in the order a player would feel them.

Log noise, not a defect

Six Keerdm Zombie Essentials loot tables fail to parse — its _vics variants, which reference Vic's Point Blank items. The first version of this page called them empty chests. Keerdm's own Lost Cities conditions (car_loot.json, chestloot.json) reference only the _tacz twins, so nothing generates from the broken tables; they are dead files shipped for a Point Blank configuration. Seventy error lines a boot, zero player impact.

Player-facing · crafting

Warium's crafting chain is dead. Twenty-nine crusty_chunks:assembly recipes fail with "invalid or unsupported recipe type", and its burnt:firestarter tag reference points at a mod that isn't installed. The jar also ships without a mixin refmap — a development build. Nothing Warium adds can be made.

Also unbuildable: Factory Blocks' two mason-table recipes (need Chipped, absent); Survival Instinct's and dtrch's recipes reference items their own jars never register.

Stability · loader

Fabric API 0.92.2 — the umbrella plus 43 API modules — is loaded inside Forge, bundled by txnilib. Moonlight logs an explicit warning that this "can easily lead to poor compatibility"; fabric-object-builder-v1 throws a mixin injection error against villager trades at runtime; fabric-screen-api-v1 tries to patch client-only classes on the dedicated server. Reading every kept jar's mods.toml settled who needs it: Chunk Activity Tracker, a minor performance mod, is the only dependent. It is cut, and txnilib leaves with it. (An earlier version of this page guessed From The Fog; the manifest says otherwise. From The Fog's failing watching:check function is a separate defect.)

Dead weight · wrong version

lostsouls-1.21-5.0.0.jar is a Minecraft 1.21 jar. It does not appear in the loaded-mod registry — Forge skipped it silently. MineTraps-1.20.2 is a 1.20.2 build running on 1.20.1; it loaded, which is luck rather than compatibility.

Noise · 586 lines per boot

Engineered Compatibility skips 586 recipes for mods that are not present (Botania, Ars Nouveau, Blood Magic, Pam's, Eidolon…). Harmless in-game; it is a third of the boot log and it hides the errors above.

Lower-impact defects, for completeness

  • LC²H (Lost Cities multithreading) targets three classes that do not exist in Lost Cities 7.4.6 — CityPlan, ServerChunkCache$ChunkHolderProvider — so part of it silently no-ops. It also runs with Debug: ENABLED. Version mismatch between the two.
  • Seven Botania recipes fail with no Botania installed; eight liquidburner fuel recipes return a null serializer. Their source is a jar, not a datapack — the world's six datapacks are unrelated (see below) — and remains unattributed; it does not survive the rebuild either way.
  • Compat mixins with absent targets, all harmless: Does It Tick → FTB Chunks; Parties → Apotheosis; Create Big Cannons → Framed Blocks; Pomkots Mechs → client Camera on the server.
  • #hordes:infection_cures tag missing — the 1.21 config folder again.
  • Guard Villagers config "not correct, correcting" on every boot — a stale file the mod rewrites each time.

TaCZ ammo has ExplosiveAmmoDestroysBlock = true. With no claims mod installed (Does It Tick is configured for FTB Chunks, which isn't there), every base is currently one explosive round away from a hole.

Two full tech trees

Create (+ Deco, + Big Cannons) and Immersive Engineering (+ Engineers Delight, + Engineered Compatibility) are both installed. The blueprint's cut list rules out large tech mods, and Create goes. Immersive Engineering is the one exception worth arguing for: its concrete, scaffolding, wiring, and diesel generators are the visual language of the setting, and its biodiesel chain is exactly the fuel economy the vehicle pillar needs. Keep IE alone, trimmed in config; cut the compat jars.

Six horror entities, all at default rates

From The Fog, Eyes in the Darkness (2–3 eyes per player at all times, cycle every 150 ticks), Horror Element Mod (21 MB, kitchen-sink), The Knocker ("common"), Dark Doppelganger (600 HP boss casting Iron's Spellbooks spells), From The Caves. Each tuned for solo play; together they are on screen constantly. The blueprint's rule stands: two entities, rare.

Three raid schedulers

The Hordes (every 10 days, midnight, 8 per wave, cap 30, infection on), Bandits (every 5–15 days, 5–10 attackers), and vanilla raids via the illager faction. They do not know about each other, so they stack. Pick The Hordes as the horde-night engine and fold the others into In Control! rules.

Theme drift

Twilight Forest and its villages, Iron's Spellbooks, Divine Weaponry, Alex's Caves (75 MB), Backrooms Eternal, Goblin Traders, Doggy Talents, Waystones, Moving Elevators, Chisel, Reddens Lanterns, Waterframes. None serve a pillar. Twilight Forest alone has 95 lines of In Control! spawn caps written for it in the backup rules file — effort spent taming a mod that should not be there.

What is worth keeping

Someone did real design work here. It carries forward.

  • The In Control! zombie-apocalypse layer. spawn.json denies all natural hostiles in the overworld except zombies, skeletons, spiders, illagers and mechs; caps zombies at 24 per player, skeletons at 4, spiders at 3; gives zombies +25% health, +8% speed, +15% follow range. spawner.json adds a custom spawner at 0.55 zombies/second in darkness, daytime pillager patrols away from villages, and rare mech spawns. It is coherent, tuned, and exactly the scaffold the faction-territory rules in the blueprint build on. The spawn BACKUP.json is an older, more elaborate version with Twilight Forest caps — the current one is the better one.
  • Mob Factions. Five factions defined — zombie, skeleton, illager, piglin, civilian — with enemies and allies, and the Knocker filed under zombie, the mechs under illager. This is the minimum viable "factions fight each other" layer, and it already works.
  • The Hordes, once its config is regenerated for 1.5.4c. Wave scaling, day-count gating, infection with zombie-player spawns, sleep blocked during the event. This is a better horde-night engine than the blueprint's Enhanced Celestials pick, and it is already tuned. The blueprint is updated to match.
  • chaoszpack + Keerdm — the TaCZ gun pack with Lost Cities loot integration and apocalypse structures. This is the curated pack the blueprint asked for. Keep, and patch the six broken loot tables with a datapack override.
  • Dynamic View is correctly configured (view 3–10, simulation 2–6, targeting 40 ms ticks) and is what makes the view-distance=32 / simulation-distance=32 in server.properties survivable. Fix the properties to match so removing Dynamic View can never detonate the server.
  • PlayerRevive (downed state, teammates revive) fits a co-op looter better than a corpse mod. Keep it; the blueprint's Corpse entry becomes optional.
  • Hostile Villages, Guard Villagers, Recruits — a civilian faction with defenders and recruitable NPCs. Keep.
  • Underground Bunkers, Doomsday Decoration, Immersive Weathering, Refurbished Furniture — the setting's set-dressing. Keep.

Player builds

Four worlds were pulled off the server and every region file was read: the July 2025 original (near-empty), the Oct–Dec 2025 world plus a September zip of it that sat in the root, the orphaned root region/, and the live world. Every chunk was decoded to its block palette; chunks were classified as built or generated, clustered into sites, and the two big worlds were matched against each other by content signature.

Finding

The live world already holds every old build. Someone transplanted them once before.

What the builds depend on

Counting only placed blocks — ores, Lost Cities filler (in this pack the city ground is IE hempcrete, millions of blocks of it) and the Backrooms dimension excluded — and only sites that do not repeat elsewhere (the apocalypse packs' chest-spawner-blast-furnace buildings recur twenty-six times; a player build is one of a kind):

  • Kept anyway: Immersive Engineering 79 k, Superb Warfare 1.1 k, Refurbished Furniture, Farmer's Delight, Doomsday Decoration.
  • Moved from cut to keep as build dependencies: factory_blocks 511 k blocks (41 kinds), chisel 96 k (62 kinds), antiblocksrechiseled 14 k (47 kinds).
  • Remapped rather than kept — 9.1 k blocks across Warium (56 kinds, mostly structural concrete and coloured armour), Create Deco catwalks, Create track and cut deepslate, Survival Instinct props, stone lanterns, Moving Elevators, Waterframes, Doggy Talents, Waystones — each mapped to a vanilla or IE block of the same role in remap.json.
  • Already missing today: Spore, DimDoors and Modern Structures blocks in the old world are worldgen from mods removed long ago, not builds.

How they move

Chunk-level transplant between region files (transplant.py): the live district rectangle — chunks x 56…193, z 24…129, blocks 896…3103 × 384…2079 — is copied into the new world at the same coordinates, plus the spawn structure and one outlier, plus the eleven never-transplanted old sites at the known offset. Block entities, ticks and heightmaps shift with the chunk; structure references are dropped; entities move from the entities/ region set; POI files are regenerated. The tool's typed NBT round-trips all 29,273 live chunks byte-for-byte, and a four-chunk trial transplant re-scanned with identical signatures.

The panel offers no backups on this plan (TooManyBackupsException: limit of 0), so the rollback is the complete local snapshot: every world, mods/, libraries/, tacz/, configs, logs and crash reports — about 2.5 GB under Minecraft Server Tools\pull\.

Coverage

Read in full: the /mods listing (138 jars), latest.log (1,761 lines), all 34 crash reports, all 962 archived logs (mod count, lag, memory, joins), all 513 files in config/ including every In Control! rule file and the faction, horde, horror and weapon configs, defaultconfigs/, server.properties, ops.json, whitelist.json, and the server's allocation and startup definition from the panel API.

Corrected after publication: the first version of this page reported that directory listings through the panel API had failed all session and attributed it to the node. That was wrong. The listings were being sent with paths rewritten by the local Git Bash shell (/mods arriving as C:/Program Files/Git/mods), and the panel answers a nonexistent path with the same DaemonConnectionException it would give for a real outage. With path conversion off, every listing works. /kubejs does not exist. The world's datapacks/ folder is listed above. The server root, both world folders and the stray directories have been inventoried. The only remaining unattributed item is which jar ships the seven Botania recipes.

Builds: all four worlds' overworld region files read in full — 63 + 16 + 6 + 49 files, 29,273 live chunks — plus the old world's nether, Twilight Forest, Backrooms and DimDoors dimensions for the dependency tally. The four [1.21] datapacks were deleted from the live world after it was copied; SBW uniforms and No More Phantoms remain.

Inferred, not read: that From The Fog is txnilib's dependent (from the jar being a universal Forge/Fabric build). Unidentified: tmted, dtrch, lrarmor — no listing found; their disposition does not depend on identity.

Review passes on this document: one structural self-check of the page, one cross-check of every count and date against the extracted outputs (which corrected three figures), one correction pass after the root listing succeeded, and one build-analysis pass whose site classifier was revised three times against the data.
